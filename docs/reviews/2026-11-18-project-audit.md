## Частина 3. Режим рендерингу й розміри бандлів вітрини

Виміряно збіркою `next build` (Next 16.3.6) на `develop@fd87d787`.

### Режим рендерингу

| Режим                              | Маршрути                                                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Статика з оновленням раз на годину | `/`, `/categories`, `/devices/[model]`                                                                     |
| Статична оболонка, дані з клієнта  | `/cart`, `/checkout`, `/account`, `/wishlist`, `/login` та інші службові                                   |
| На кожен запит                     | `/products`, `/products/[slug]`, `/categories/[slug]`, `/catalog`, `/search`, `/promo`, `/blog`, `/info/*` |

- Сторінка товару й каталог рендеряться на кожен запит. Це свідоме рішення: ціна й залишок не можуть застаріти в кеші Next.
- Статичні сторінки з цінами (`/`, `/categories`, `/devices/[model]`) скидаються викликом `/api/revalidate` з API після кожного запису в каталог; годинний таймер — страховка.
- `/promo` рендериться на кожен запит, хоча коментар у `revalidate-targets.ts` називає її статичною. Шкоди немає, коментар застарів.

### Звідки може взятись застаріла ціна

| Шар                            | Скільки живе стара ціна             | Чим закрито                                         |
| ------------------------------ | ----------------------------------- | --------------------------------------------------- |
| Кеш Redis в API                | до 5 хв (`REDIS_CACHE_TTL_SECONDS`) | скидання при записі товару (`evictProductDetail`)   |
| Статичні сторінки Next         | до 1 год, якщо вебхук не дійшов     | `/api/revalidate` після запису                      |
| Відкрита вкладка (React Query) | до 5 хв (`staleTime`)               | оновлення при поверненні у вкладку й кнопці «Назад» |
| Кошик і замовлення             | не живе                             | ціна береться з бази в момент запиту                |

Отже, покупець не може заплатити стару ціну: замовлення рахує сервер. Найгірший випадок — у відкритій вкладці до 5 хвилин видно стару ціну, а в кошику вже нова. Чи попереджає вітрина про таку зміну — не перевірялось.

### Розміри бандлів

- Усього JavaScript вітрини: 37 файлів, 2220 кБ, 648 кБ у gzip.
- **Кожна сторінка завантажує 26–27 із цих 37 файлів — близько 630 кБ у gzip** (звірено на `/`, `/cart`, `/checkout`, `/categories`, `/login`, `/wishlist`). Сторінка входу тягне стільки ж коду, скільки чекаут: поділу коду за маршрутами фактично немає.
- Найбільший файл — 129 кБ у gzip — це Sentry разом із записом сесій.
- CSS — 30 кБ у gzip, це нормально.

Для магазину орієнтир — до 200 кБ JavaScript у gzip на першому екрані. Перевищення втричі найбільше б'є по телефонах із повільним інтернетом. Адмінку не міряли.
