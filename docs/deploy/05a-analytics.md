# 5a. Аналітика: увімкнути Umami (TASK-378/379/380)

**Коли робити:** після першого вдалого деплою (крок 5), до передачі магазину замовнику.
**Скільки часу:** ~20 хвилин, з них половина — перезбірка вітрини.
**Що буде, якщо пропустити:** нічого не зламається, але **статистики не існуватиме взагалі** —
ні в Umami, ні в адмінці. Це найпідступніший стан у всьому деплої: усі контейнери «здорові»,
помилок ніде немає, а даних немає. І зібрати їх заднім числом неможливо — трафік, який не
записали, втрачено назавжди.

---

## 0. Чому це окремий крок, а не рядок в `.env`

Лічильник відвідувань вантажить **браузер покупця**, а не наш сервер. Тобто в Umami має бути
публічна адреса — інакше в HTML вітрини нема чого підставити. До TASK-378 такої адреси не
було: Umami слухала лише `127.0.0.1:3003`, дістатись до неї можна було тільки через SSH-тунель.

І друге: адреса скрипта та ID сайту **вшиваються у вітрину під час збірки** (це `NEXT_PUBLIC_*`).
А ID сайту неможливо знати заздалегідь — його видає сама Umami, коли ви створите в ній сайт.
Тому порядок жорсткий і двофазний: **підняти → створити сайт → вписати → перезібрати**. Просто
дописати змінні в `.env.production` і зробити `restart` — **не спрацює**.

---

## 1. Adреса в DNS

Додайте A-запис `analytics.<домен>` на IP прод-сервера — так само, як `admin.` і `api.`
(див. [02-domain-dns.md](02-domain-dns.md), розділ 1). Дочекайтесь, поки він резолвиться:

```bash
nslookup analytics.shop.<домен>
```

Caddy побачить блок `analytics.{$DOMAIN}` у `Caddyfile` і сам випише сертифікат при
першому запиті.

---

## 2. ⚠ Спершу змініть пароль Umami

**Зробіть це ДО того, як адреса почне відкриватись.** У свіжої Umami стандартний логін
`admin` / `umami` — і він однаковий у кожної інсталяції в світі.

Поки Umami була видима лише з самого сервера, це було терпимо. З публічною адресою це
означає, що будь-хто, хто знає, що ви користуєтесь Umami, зайде у вашу панель.

```bash
cd /opt/case-store
COMPOSE="docker compose -f docker-compose.prod.yml --env-file .env.production"

# Тунель з ноутбука, поки DNS ще не вказує на сервер:
#   ssh -L 3003:127.0.0.1:3003 <користувач>@<IP сервера>
# і відкрийте http://localhost:3003
```

Увійдіть → **Settings → Profile → Change password**. Пароль збережіть у менеджері паролів
(див. [01-accounts-access.md](01-accounts-access.md)).

---

## 3. Створіть сайт і візьміть його ID

У Umami: **Settings → Websites → Add website**.

| Поле   | Значення                        |
| ------ | ------------------------------- |
| Name   | назва магазину                  |
| Domain | `shop.<домен>` (без `https://`) |

Після збереження відкрийте сайт → **Edit** (або «Tracking code»). Вам потрібні два значення:

- **Website ID** — UUID виду `3b1c…`;
- адреса скрипта — це завжди `https://analytics.<домен>/script.js`.

---

## 4. Окремий користувач для адмін-панелі

Картка «Відвідуваність» в адмінці показує цифри через **наш** API, а не через Umami напряму —
щоб пароль не потрапив у браузер. Нашому API потрібен власний обліковий запис.

**Settings → Users → Create user**: логін напр. `store-api`, довгий пароль. Дайте йому доступ
до створеного сайту (**Settings → Websites → <сайт> → Members**, роль «View only», якщо ваша
версія Umami її пропонує).

Не використовуйте для цього логін власника: його пароль колись зміниться — і картка мовчки
згасне.

---

## 5. Впишіть значення

У `/opt/case-store/.env.production`:

```bash
# Вітрина: сам лічильник (вшивається у збірку)
NEXT_PUBLIC_UMAMI_SRC=https://analytics.shop.<домен>/script.js
NEXT_PUBLIC_UMAMI_WEBSITE_ID=<UUID з кроку 3>

# Адмінка: посилання «Відкрити Umami» (вшивається у збірку)
NEXT_PUBLIC_UMAMI_DASHBOARD_URL=https://analytics.shop.<домен>/websites/<UUID>

# API: цифри в картці «Відвідуваність» (читається під час роботи, НЕ при збірці)
UMAMI_API_URL=http://umami:3000
UMAMI_API_USERNAME=store-api
UMAMI_API_PASSWORD=<пароль із кроку 4>
UMAMI_WEBSITE_ID=<той самий UUID>

# CSP самого API. На завантаження лічильника не впливає — у вітрини CSP немає.
UMAMI_ORIGIN=https://analytics.shop.<домен>
```

> **`UMAMI_WEBSITE_ID` і `NEXT_PUBLIC_UMAMI_WEBSITE_ID` — те саме значення.** Розійдуться —
> вітрина писатиме в один сайт, а адмінка показуватиме інший, і обидві виглядатимуть
> справними.

## 6. Перезбірка (без неї кроки 1–5 нічого не дають)

Три `NEXT_PUBLIC_*` вище вшиваються під час збірки образів, тож потрібні **нові образи**
вітрини й адмінки. `UMAMI_API_*` читаються під час роботи, тож для них досить рестарту.

**Якщо деплоїте через CI** (звичайний шлях): впишіть ці значення у змінні оточення
GitHub Environment (див. [04-secrets-ci.md](04-secrets-ci.md)) і зробіть новий пуш у `develop` —
джоба перезбере образи з новими значеннями.

**Якщо збираєте на сервері:**

```bash
cd /opt/case-store
COMPOSE="docker compose -f docker-compose.prod.yml --env-file .env.production"

$COMPOSE build store-client store-admin
$COMPOSE up -d store-client store-admin store-api
```

---

## 7. Перевірка — три речі, і всі три обов'язкові

**7.1 Скрипт віддається.** З ноутбука:

```bash
curl -sI https://analytics.shop.<домен>/script.js | head -1
```

Має бути `200`. Якщо `404` — Umami піднялась, але адреса скрипта інша; якщо не резолвиться —
поверніться до кроку 1.

**7.2 Лічильник справді стоїть на вітрині.** Відкрийте магазин у браузері → F12 → вкладка
Network → перезавантажте. Має бути запит на `script.js` зі статусом 200 і, після переходу на
іншу сторінку, запит `POST /api/send`.

> Якщо `script.js` немає в списку взагалі — вітрину зібрано **без** значень. Це крок 6, а не
> крок 1: змінні є, але у старому образі їх немає.

**7.3 Цифри доходять.** У самій Umami сторінка сайту має показати ваш візит (за хвилину-дві).
Тоді відкрийте адмінку → головна → картка «Відвідуваність»: там мають бути ті самі числа.

| Що бачите в картці                            | Що це означає                                                       |
| --------------------------------------------- | ------------------------------------------------------------------- |
| Числа                                         | усе працює                                                          |
| «Дані аналітики зараз недоступні»             | `UMAMI_API_*` задані, але API не достукався: пароль/ID/адреса       |
| Тільки посилання «Відкрити Umami»             | `UMAMI_API_*` не задані — крок 5 пропущено або образ не перезібрано |
| «Ще не підключено. Зверніться до розробника.» | не задано і `NEXT_PUBLIC_UMAMI_DASHBOARD_URL`                       |

---

## 8. Staging

Те саме, з однією відмінністю: у `Caddyfile.staging` під паролем **уся** Umami, крім
`/script.js` і `/api/send`. Це навмисно — під паролем лічильник не завантажився б, і staging
«мав би аналітику», яка нічого не пише.
