# Executive Summary — store-ai

> Інтернет-магазин мобільних аксесуарів (B2C) з адмін-панеллю.
> Monorepo (npm workspaces): NestJS API + два Next.js застосунки (вітрина та адмінка).
> _Підготовлено на основі `BACKLOG.md` та аналізу коду._

---

## Статус проєкту: MVP функціонально завершений

Завершено **5 фаз розробки** — від інфраструктури до production-полірування. Повний цикл
покупки працює: каталог → кошик → оформлення → замовлення → адмін-обробка. Зараз триває
фаза стабілізації та якості (тести, локалізація, надійність).

## Що працює (готове до використання)

| Напрям           | Готовність                                                                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Покупка**      | Каталог з фільтрами, картка товару з варіантами та фото, кошик для гостей і зареєстрованих, оформлення замовлення (адаптоване під ринок України), email-підтвердження |
| **Користувачі**  | Реєстрація/логін, JWT + refresh-токени, особистий кабінет, історія замовлень                                                                                          |
| **Адмін-панель** | Дашборд з метриками (виручка, замовлення, залишки), CRUD товарів/категорій, керування замовленнями та користувачами                                                   |
| **Безпека**      | Argon2-паролі, RBAC, rate limiting, Helmet, CSRF, валідація — рівень production                                                                                       |
| **Локалізація**  | Українська мова + гривня на вітрині                                                                                                                                   |

## Технічна зрілість

- **Архітектура:** Clean Architecture (backend), Feature-Sliced Design (frontend) — чітке розділення шарів
- **Контракт API:** автогенерація типів/хуків (OpenAPI + Orval) — фронтенд і бекенд завжди синхронні
- **Якість:** ~25 unit + 12 e2e тестів на бекенді, компонентні тести на вітрині, CI (lint/typecheck/test/build)
- **Спостережуваність:** структуроване логування (Pino), Redis-кешування, SEO (sitemap, JSON-LD)
- **DevOps:** Docker-compose, GitFlow, pre-commit хуки

## Залишковий обсяг

- **Найближче (якість):** добити локалізацію адмінки, прогнати E2E на живому стенді, Sentry, надійна доставка email
- **Зростання виручки:** відгуки, промокоди, інтеграція з Новою Поштою
- **Конверсія:** повнотекстовий пошук (Meilisearch), wishlist, оптимізація зображень
- **Свідомо відкладено:** реальні платежі (Stripe/LiqPay/Fondy) — до підтвердження попиту; маркетингова автоматизація (кинуті кошики, GA4/Pixel)

## Підсумок

Платформа технічно зріла, добре структурована та протестована. Для повноцінного комерційного
запуску бракує переважно **онлайн-оплати** та **логістики (Нова Пошта)** — обидва свідомо
заплановані як наступні кроки. Детальний gap-аналіз проти живих конкурентів — нижче.

## Що зробити **ПЕРЕД** реальним деплоєм (must-have для запуску)

1. **Платежі** — підключити мінімум один UA-провайдер (LiqPay або Mono), вебхуки статусів,
   звірка `PaymentStatus`. _(TASK-034/081 — зараз 🅿️, треба підняти у пріоритеті)_
2. **Нова Пошта** — інтеграція API: автокомпліт міста+відділення, вартість і ETA в checkout. _(TASK-080)_
3. **Юридика та контент** — Оферта, Політика конфіденційності, Умови повернення/доставки,
   сторінка «Контакти» з реквізитами ФОП/ТОВ. (Передумова для підключення платіжки.)
4. **Стабілізація вже зробленого** — закрити _Pending manual QA_: застосувати міграцію
   soft-delete на проді, прогнати Playwright E2E на живому стенді, smoke checkout + admin CSRF/refresh.
5. **Прод-готовність інфраструктури**:
   - Реальні секрети/`.env` на проді, ротація JWT-секретів, `secure` cookie + HTTPS/TLS
   - Бекапи PostgreSQL, міграції через `prisma migrate deploy` (не `db push`)
   - Sentry увімкнено (frontend + backend) — TASK-048
   - CORS звужено до прод-домену, перевірити rate-limit ліміти під реальний трафік
   - Доставка email через реальний SMTP/провайдер (не fire-and-forget) — TASK-103
   - CDN + оптимізація зображень (`next/image`, WebP/LQIP) — TASK-074/091
   - Health-checks та моніторинг аптайму
6. **Базовий пошук** — хоча б простий пошук по назві, навіть до Meilisearch (магазин без пошуку нежиттєздатний).
7. **Юзабіліті-мінімум для UA-покупця** — «Купити в 1 клік», кнопки Viber/Telegram + телефон, графік роботи.

## Короткий висновок

store-ai **технічно перевершує** типового конкурента за якістю архітектури, тестів і адмінки,
але **функціонально не дотягує** у трьох речах, без яких магазин в Україні не запуститься:
**онлайн-оплата, Нова Пошта і юридичні сторінки**. Це і є головний фокус «перед деплоєм».
Решта прогалин (відгуки, купони, пошук, wishlist, лояльність) — це вже **ітерації після запуску**
для зростання конверсії, і більшість із них уже стоять у backlog із заготовленими моделями даних.
