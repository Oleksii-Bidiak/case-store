## Навіщо

Замовник пробує адмінку на демо-стенді, щоб сформулювати побажання. Перше, що він зустрічає:

- Кнопки, які нічого не роблять: у менеджера без `orders:write` є «Змінити статус», API відповідає
  403, а тост каже «хтось інший змінив замовлення».
- Написи, що посилаються на неіснуючі місця меню: «Налаштування → Контакти», «Права доступу».
- Одна річ під різними назвами в меню й у заголовку.
- Сирі ключі прав у профілі.

Жодне з цього не зламано в даних, але кожне вчить не довіряти панелі. Хвиля окрема, бо в неї свій
критерій готовності — «замовник проходить адмінку без пояснень розробника», і вона має
змержитись **до** того, як артборди адмінки (сесії Д-е плану [189](189-design-track-cycle-2.md))
зафіксують базу для редизайну.

Вигляд (верстка 732/734) сюди не входить — він іде в Д-ж і хвилю [198](198-admin-by-mockups.md).

## Приймання

- **715, 716.** Без відповідного `:write` кнопки й селекти **не рендеряться** (не вимкнені). RTL на
  кожну форму: роль без права не бачить дії. Playwright: менеджер без `orders:write` відкриває картку
  і не має жодного контролу зміни. AD-ORD-34 → `[🔁]`.
- **630.** Запит «чи є заявка» вмикається за `returns:read`, а не `returns:write`; RTL на роль із
  самим `returns:write`.
- **639.** Менеджер без `staff:read`/`audit:read` на `/staff*` і `/audit-log` бачить одну чисту
  відмову (той самий компонент, що в інших розділах), а не дві червоні плашки.
- **722.** Лічильники «Замовлення»/«Відгуки» в меню гейтяться правом розділу, а не `analytics:read`.
- **724, 842.** Картка замовлення показує заявки на повернення з лінком. Для «Скасовано» і «Частково
  повернуто» замість порожнечі — пояснення й лінк на `/returns`. AD-ORD-35 → `[🔁]`.
- **718, 719, 720, 721, 725, 726, 727.** Жоден напис не посилається на пункт меню, якого немає, —
  перевірка grep-ом по словнику за назвами пунктів з `admin-nav-list.tsx`. Одна сутність — одна
  назва в меню й заголовку. Права в профілі — українськими назвами з каталогу.
- **729, 816.** Мертві ключі прибрано. Тест-гард (як у вітрині), що кожен ключ словника має
  споживача, або задокументований виняток для динамічного доступу.
- **717.** Колонка «Категорія» показує листову категорію товару для всіх позицій (RTL + e2e на
  підкатегорію 3-го рівня).
- **728.** OG-поле в товарі й категорії має завантаження й медіатеку.
- **831.** Id бренду видно й можна скопіювати. SF-CAT-32 → `[🔁]`.
- **857.** `admin-guide.md` і `admin-tour.md` описують адмінку такою, якою вона стала після хвилі.
  Перевірка — пройти `admin-tour.md` на локальній збірці крок за кроком.

## Ризики

- **Ховати, а не вимикати.** Вимкнена кнопка без пояснення — та сама «мовчазна кнопка» з ревʼю
  якості. Для ролей без права дія не рендериться. Якщо розділ без права стає порожнім — один рядок
  «Ви можете переглядати, але не змінювати».
- **Серверний гард лишається єдиним бар'єром.** UI-гейт — зручність. Тести на 403 з API не
  прибирати.
- **Словник редагують три хвилі циклу** (191, 195, 198). Ключі в кінець блоків; у M-сесії конфлікти
  в `dictionary.ts` розв'язуються збереженням ключів обох сторін.
