## Навіщо

Сесії Д-е перенесли адмінку в Claude Design такою, як вона є. Сесія Д-ж з власником виправила
артборди: зібрала з BACKLOG проблеми адмінки й прибрала їх на канвасі. Ця хвиля переносить
виправлене в код **екран за екраном**, з одним правилом: **функціональність не регресує**.

Кожен екран — окремий крок: реалізація, потім тести, потім коміт. Тільки після цього береться
наступний екран. Масштаб — уся адмінка (рішення власника 2026-09-23), тому хвиля може йти кількома
сесіями в тому самому worktree. Порядок екранів — пріоритет реєстру плану 189.

## Порядок екранів

1. **База:** оболонка (сайдбар, шапка, мобільна шухляда), дашборд, замовлення (список, картка,
   нове), товари (список, картка, форма), персонал (список, картка, шаблони), категорії (дерево,
   форма), налаштування (контакти, SEO, пошук), профіль, вхід.
2. **CRM:** повернення, відгуки, клієнти, звернення, підписники, журнал дій.
3. **Контент:** сторінки, блог, банери, каруселі, FAQ, карта контенту, медіатека.
4. **Каталог і маркетинг:** бренди, пристрої, послуги, групи товарів, знижки, імпорт, прев'ю товару.

## Кластери

Екрани одного блоку, що не ділять файлів `widgets/` і `features/`, можна робити паралельними
агентами. Спільні зміни `shared/ui` робляться **першим кроком блоку** одним агентом. Приклад —
новий варіант таблиці, якого вимагає макет. Решта агентів блоку стартує вже на оновлених
примітивах. Щойно змінились `shared/ui` або `globals.css`, потрібен синк дизайн-системи адмінки і
копія `_ds` у «store-admin — Pages». Це крок наприкінці блоку, а не наприкінці хвилі.

## Приймання

Приймання однакове для кожного екрана:

- Екран збігається з артбордом (1440 і 390). Скриншот Playwright поруч із `render_preview`
  артборда — у звіті.
- Усі наявні тести адмінки зелені: `npm run test -w apps/store-admin -- --runInBand`.
- Playwright admin-проєкт зелений: `npm run test:e2e:pw -- --project=admin`.
- Кожен змінений компонент має RTL-тест на те, що змінилось: новий стан, нову дію, новий порожній
  стан. Тест пишеться до зміни, якщо змінюється поведінка.
- Жодна дія, доступна до зміни, не зникла без рядка в переліку Д-ж, який це дозволяє.
- Права: кожна нова кнопка гейтиться тим самим `can()`, що й стара (правило хвилі 191).

## Перевірка

Після кожного екрана:

```
npm run test -w apps/store-admin -- --runInBand
npm run test:e2e:pw -- --project=admin
```

Наприкінці блоку додатково запускаються `npm run typecheck`, `npm run lint` і синк дизайн-системи
адмінки, якщо змінились `shared/ui` чи `globals.css`.

## Ризики

- **Масштаб.** Якщо блок не вміщається в сесію, це не причина мержити половину блоку. Сесія
  зупиняється після зеленого екрана, наступна продовжує в тому самому worktree (памʼять
  `worktree-session-history-location`).
- **`dictionary.ts` адмінки.** Нові ключі йдуть у кінець блоків. Написи, погоджені в Д-ж,
  переносяться дослівно.
- **Нові екрани тут не робляться.** Це `/settings/delivery`, `/home`, `/analytics`,
  `/settings/notifications` і діалог видалення категорії. Вони входять у UI-частини планів 184–188
  за макетами Д-н2.
