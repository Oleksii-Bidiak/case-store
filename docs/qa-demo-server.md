# Ручний прогін на демо-сервері — похідний чекліст

> 🚨 **Адреси нижче — приклад, а не ваш сервер.** `203.0.113.10` належить діапазону, який
> стандарт (RFC 5737) відвів під документацію: реальних машин там не буває. Перегенеруй
> файл зі своєю IP, інакше перший же пункт відкриє неіснуючий сайт.

> ⚙️ **Цей файл згенерований. Руками не редагуй** — правки затре наступний запуск.
> Джерело: [`qa-manual-full.md`](qa-manual-full.md). Перегенерувати:
> `node scripts/qa-demo-checklist.js 203.0.113.10`
>
> **Що це.** Той самий вичерпний чекліст, але під тимчасове демо на `nip.io`
> (`deploy/03b-test-deploy-no-domain.md`): адреси підставлені, а перевірки, яких на демо
> не зробити, помічені й **не мають чекбокса**, щоб не роздували підсумок.
>
> **Ідентифікатори `ЗОНА-nn` збережені** — можеш посилатись на них у BACKLOG нарівні з
> основним чеклістом.

## Як читати позначки

| Позначка | Значення                                                                   |
| -------- | -------------------------------------------------------------------------- |
| `- [ ]`  | звичайна перевірка — проходь як є                                          |
| 🔧       | та сама перевірка, але **інша дія** на сервері — читай примітку            |
| ⛔       | на демо **не робиться**; причина вказана. Чекбокса немає навмисно          |
| ⚠️       | пункт **очікувано червоний** — відомий розрив, підтвердження, не відкриття |

**Про ⛔ чесно.** Список складений за конфігурацією демо (пошта вимкнена, LiqPay не
налаштований, бекапів немає), а не за здогадами. Де було неясно — пункт **лишений
робочим**: хибне ⛔ ховає справжній дефект за словами «тут і не мало працювати», а зайва
перевірка коштує десять секунд. Тож відсутність позначки не означає «точно працює».

## Крок 0. Підготовка (демо вже підняте)

Локального стенда тут немає: ні `docker compose up`, ні `npm run db:seed` — усе це вже
зробили кроки 6–7 ранбука `03b`. Перед прогоном переконайся лише в чотирьох речах.

1. **Стек живий:** `$COMPOSE ps` → усі контейнери `Up`/`healthy`.
2. **API відповідає:** `curl -sI https://api.203-0-113-10.nip.io/health` → `200`.
3. **Каталог на місці:** відкрий https://203-0-113-10.nip.io → товари, каруселі, банери.
4. **Фото видно, а не заглушки.** Якщо замість фото сірі плитки — далі йти немає сенсу,
   половина зон дасть ❌ через дані. Причини й лікування — `03b` крок 7.6.

**Акаунти.** Адмін — той, що ти задав у `ADMIN_SEED_EMAIL`/`ADMIN_SEED_PASSWORD` на
кроці 7.4. Покупець — `customer@store.com` / `Customer123!` (пароль опублікований у
`seed-guide.md`, і на демо це прийнятно рівно тому, що демо викидне).

> ⚠️ **Демо публічне і без пароля.** Усе, що ти тут наробиш, видно будь-кому, хто знає
> адресу. Не заводь реальних персональних даних — ні своїх, ні замовника.

## Що робити з кожним ❌

1. **Не чіпай код.** Твоє завдання — зафіксувати, а не полагодити. Половина «очевидних»
   виправлень ламає щось інше.
2. **Опиши в самому рядку**, у квадратних дужках: що зробив, що очікував, що побачив.
   Достатньо одного речення — але конкретного. «Не працює» — не опис.
3. **Прикріпи докази**, якщо вони є: скріншот, текст помилки з червоної консолі (F12 →
   Console), відповідь сервера (F12 → Network → клік по запиту → Response).
4. **Перевір, чи це не ⚠️-пункт.** Пункти з цією позначкою червоні за задумом — розрив уже
   відомий. Такий ❌ не заводить нову задачу.
5. **Заведи рядок у [`BACKLOG.md`](../BACKLOG.md)** з наступним вільним ID (дивись шапку
   BACKLOG) і поміть, наскільки це важливо: гроші/дані/безпека → 🔴; заважає роботі → 🟡;
   косметика → 🟢.
6. **Продовжуй прогін.** Одне ❌ не зупиняє зону — далі можуть бути ще п'ять.

Наскрізне: AD-AUTH-10 (вихід), AD-PUB-01…08 (публікація й кеш зачіпають кілька розділів
одразу), AD-SET-10 і AD-SET-11 (пошук і доставка — API без власного екрана).

## Додаток Б — «дозвіл → перевірка»

Доказ повноти для RBAC: усі **32** права з
`apps/store-api/src/auth/permissions/permission.catalog.ts`, згруповані так само, як їх
показує екран матриці. Кожне має щонайменше одну перевірку.

> Загальний шаблон перевірки права: увійди менеджером **із** правом → дія проходить;
> увійди менеджером **без** нього → пункту в меню немає, а прямий URL і прямий виклик API
> дають 403. Пункти нижче конкретизують «дію» для кожного права.

### Поза матрицею: зони, які не грантуються нікому

Три області захищені `@OwnerOnly()` і **навмисно відсутні** в каталозі прав. Причина
записана в самому каталозі: право редагувати матрицю — це право видати собі будь-що, після
чого вся матриця стає декоративною. Тому власник ніколи не підпадає під матрицю, а ці
екрани не можна віддати менеджеру навіть свідомо.

| Область                                                            | Маршрут / ендпоінт                                       | Перевірки                          |
| ------------------------------------------------------------------ | -------------------------------------------------------- | ---------------------------------- |
| Керування користувачами (створення, роль, чужий пароль, видалення) | `/users`, `POST /api/users`, `PATCH /api/users/:id/role` | AD-CRM-10, AD-CRM-11, AD-CRM-12    |
| Матриця прав                                                       | `/settings/permissions`                                  | AD-RBAC-01, AD-RBAC-02, AD-RBAC-06 |
| Журнал дій                                                         | `/audit-log`                                             | AD-RBAC-12, AD-RBAC-18             |
